## 1. Як це все влаштовано за дві хвилини

Сайт **статичний**. Це означає: немає жодної бази даних і жодного сервера,
який щось обчислює. Є набір готових сторінок, які просто лежать і
віддаються відвідувачу. Тому сайт швидкий, майже неможливо зламати, і його
розміщення нічого не коштує.

Ланцюжок, за яким усе живе:

```
Ви змінюєте файл  →  GitHub це помічає  →  автоматично збирає сайт  →  сайт оновлюється
                                              (2–3 хвилини)
```

**GitHub** — це сховище, де лежить увесь проєкт. Заразом він і публікує сайт.
Ви нічого не платите.

Найважливіше, що варто засвоїти: **увесь текст сайту лежить в окремих
текстових файлах, а не всередині коду**. Щоб додати питання до FAQ або нове
завдання, програмувати не треба — треба відредагувати текстовий файл за
зразком сусіднього запису.

## 3. Найпростіший спосіб щось змінити — прямо в браузері

**Це головний спосіб роботи для вас.** Нічого встановлювати не треба,
командний рядок не потрібен.

1. Відкрийте https://github.com/Suhrobss/unionize
2. Клацніть теку **`data`** — там лежать усі тексти сайту
3. Клацніть потрібний файл, наприклад **`faq.json`**
4. Угорі праворуч натисніть **олівець** (підказка «Edit this file»)
5. Змініть текст просто у вікні браузера
6. Прокрутіть униз, у полі **Commit changes** коротко напишіть, що ви
   зробили — наприклад «додав питання про аукціон»
7. Натисніть зелену кнопку **Commit changes**

Усе. За дві-три хвилини зміни з'являться на сайті. Перевірити хід публікації
можна на сторінці **Actions** (адреса вище).

> **Порада.** Перед першою серйозною зміною спробуйте щось безневинне —
> виправте кому в якомусь тексті. Побачите весь ланцюжок від початку до
> кінця й перестанете хвилюватися.

## 4. Що де лежить

Тек багато, але вам потрібні здебільшого дві: `data` і `public/images`.

### Теки, з якими ви працюєте

| Тека | Що всередині |
|---|---|
| **`data`** | **Усі тексти сайту.** Питання FAQ, завдання, вікторина, клітинки поля, тест архетипу |
| **`public/images`** | Усі зображення: поле, фото людей, картинки для соцмереж |

### Теки, які краще не чіпати без потреби

| Тека | Що це |
|---|---|
| `src` | Код сайту: сторінки, вигляд, поведінка |
| `src/config` | Невеликі налаштування: меню, посилання, адреса таблиці рейтингів |
| `public/fonts` | Шрифти |
| `.github` | Опис того, як сайт публікується автоматично |

### Файли в корені

| Файл | Що це |
|---|---|
| `README.md` | Короткий опис проєкту для тих, хто зайде в сховище |
| `ІНСТРУКЦІЯ.md` | Цей файл |
| `package.json` | Список бібліотек, від яких залежить сайт |
| `.gitignore` | Список того, що НЕ потрапляє у сховище |

> **Важливо.** Тека `docs` (правила гри, технічні завдання), тека `reference`
> (оригінал зображення поля) і службові скрипти **не потрапляють на GitHub** —
> вони є тільки на вашому комп'ютері. Так вирішено свідомо, щоб внутрішні
> матеріали не стали доступні всім. Тому **не видаляйте їх зі свого
> комп'ютера — резервної копії в інтернеті немає.**

## 5. Як змінювати тексти: покроково для кожного файлу

Усі файли в теці `data` мають однакову будову: спочатку блок `_meta` з
поясненнями, потім список записів. Щоб додати новий запис — скопіюйте
сусідній і замініть у ньому текст.

### 5.1. Питання-відповіді на сторінці «Правила» — `data/faq.json`

Зараз там 25 питань. Один запис виглядає так:

```json
{
  "id": "faq-01",
  "category": "start",
  "question": "Хто починає гру першим?",
  "answer": [
    { "type": "p", "text": "Той, хто викине більше очок." }
  ]
}
```

- `id` — унікальна позначка. У нового запису має бути своя, наприклад `faq-26`
- `category` — до якої групи належить питання. Дозволені: `start`, `cells`,
  `situations`, `calculator`, `other`. Ці групи стають кнопками-фільтрами
  над списком питань
- `question` — саме питання
- `answer` — відповідь. Це список блоків, бо відповідь може бути складною

Типи блоків у відповіді:

```json
{ "type": "p", "text": "Звичайний абзац тексту." }

{ "type": "subhead", "text": "Підзаголовок усередині відповіді" }

{ "type": "list", "items": ["перший пункт", "другий пункт"] }
```

Числа в тексті окремо позначати не треба — сайт сам виділяє їх шрифтом.

### 5.2. Завдання для «Додаткової можливості» — `data/tasks.json`

```json
{
  "id": "task_oleg_01",
  "title": "Підписатися в соцмережі",
  "steps": [
    {
      "action": "Підпишіться на Instagram голови профспілки",
      "url": "https://www.instagram.com/og3003",
      "button_label": "Відкрити"
    }
  ],
  "verify_hint": "Покажіть ведучому, що ви підписані",
  "active": true
}
```

- `steps` — кроки завдання. Їх може бути кілька; сайт покаже їх по черзі
- `url` і `button_label` — необов'язкові. Якщо їх немає, буде просто текст
- `verify_hint` — що гравець показує ведучому як доказ
- **`active`** — головний перемикач. `true` — завдання показується,
  `false` — лежить у файлі, але гравцям не випадає

Щоб тимчасово прибрати завдання, не видаляйте його — просто змініть
`"active": true` на `"active": false`.

### 5.3. Вікторина — `data/quiz.json`

```json
{
  "id": "geo_01",
  "topic": "морська географія",
  "question": "Який океан є найбільшим за площею?",
  "options": ["Тихий", "Атлантичний", "Індійський", "Північний Льодовитий"],
  "correct": 0,
  "explanation": "Площа Тихого океану — близько 165 200 000 км².",
  "status": "ready"
}
```

- `options` — варіанти відповіді
- **`correct`** — номер правильного варіанта. **Лік починається з нуля!**
  `0` — перший варіант, `1` — другий, `2` — третій, `3` — четвертий.
  Це найчастіше джерело помилок — перевіряйте двічі
- `explanation` — пояснення, яке гравець бачить після відповіді
- **`status`** — у вікторину потрапляють **тільки** записи зі
  `"status": "ready"`. Усе інше лежить у файлі про запас і не показується

### 5.4. Клітинки ігрового поля — `data/board-cells.json`

```json
{
  "id": "start",
  "name": "Старт",
  "type": "Старт",
  "side": "top",
  "x": 0, "y": 0, "w": 14, "h": 14,
  "story": "",
  "link": ""
}
```

- `name` — назва клітинки, яку бачить відвідувач
- `type` — тип клітинки. Дозволені рівно сім: `ППО`, `Події`, `Ресурси`,
  `Криза`, `Відпочинок`, `Старт`, `Бонуси`
- `story` — текст, що з'являється, коли клітинку відкривають. Можна дописувати
- `link` — посилання на сайт закладу, якщо є
- **`x`, `y`, `w`, `h`** — розташування клітинки на зображенні поля,
  **у відсотках**. Їх краще не чіпати: вони підібрані під конкретне
  зображення. Якщо колись зміниться арт поля, ці числа треба буде
  перерахувати — скажіть мені, я зроблю

### 5.5. Тест архетипу — `data/archetype-questions.json` і `data/archetypes.json`

Ці два файли пов'язані між собою складніше за інші: у питаннях є «осі»
(`axis`) і «полюси» (`pole`), від комбінації яких залежить, який саме
архетип випаде людині.

**Правити тексти тут можна, а от додавати чи видаляти питання — ні:**
зміна кількості питань розбалансує підрахунок, і результати стануть
неправильними. Якщо треба змінити склад питань — краще скажіть мені.

Безпечно міняти: формулювання питань і варіантів, описи архетипів
(`aboutYou`, `strengths`, `blindSpot`, `howYouPlay`, `lifeMeaning`).

## 6. Правила, які не можна порушувати в текстових файлах

Файли з розширенням `.json` дуже вимогливі до розділових знаків. Якщо
помилитися, сайт не збереться — але **нічого страшного не станеться**: на
сайті просто залишиться попередня версія, а на сторінці Actions з'явиться
червоний хрестик.

Чотири правила, яких досить:

**1. Текст завжди в подвійних лапках**

```
Правильно:   "question": "Хто починає гру?"
Неправильно: "question": Хто починає гру?
```

**2. Між записами — кома, після останнього — ні**

```json
[
  { "id": "a" },
  { "id": "b" },
  { "id": "c" }
]
```

Після `{ "id": "c" }` коми немає — це остання.

**3. Лапки всередині тексту треба екранувати**

Якщо в тексті потрібні лапки, ставте українські «ялинки» — вони
безпечні. Прямих подвійних лапок усередині тексту уникайте.

```
Правильно:   "text": "Гравець створює «ППО»"
Небезпечно:  "text": "Гравець створює "ППО""
```

**4. Кожна відкрита дужка має бути закрита**

Найпростіший спосіб не помилитися — не писати запис з нуля, а
**скопіювати сусідній і замінити в ньому текст**.

> **Як перевірити себе.** Скопіюйте вміст файлу на https://jsonlint.com,
> натисніть Validate. Зелений напис — усе гаразд.

## 7. Як замінити зображення

Зображення лежать у `public/images`. Найважливіші:

| Файл | Де використовується |
|---|---|
| `board/board-tex.jpg` | Поле в тривимірній сцені на головній і в макеті сторінки «Поле» |
| `board/board-lg.jpg` | Поле у великому масштабі, коли натиснути «Дивитись поле» |
| `board/board-hero.jpg` | Запасний фон |

| `hero/card-face.webp` | Картка, що прилітає в сцені |

Щоб замінити картинку через браузер: відкрийте потрібну теку в сховищі,
натисніть **Add file → Upload files**, перетягніть новий файл **з такою
самою назвою**, натисніть **Commit changes**.

**Важливо про розмір.** Не завантажуйте величезні файли з фотоапарата.
Зображення понад 1 МБ сильно сповільнить сайт на телефоні. Якщо треба
замінити поле — надішліть мені оригінал, я підготую всі потрібні розміри
правильно.

## 8. Рейтинги: таблиця гравців

Сторінка «Рейтинги» бере дані з Google-таблиці. **Код чіпати не треба** —
змінюєте таблицю, і сайт підхоплює це сам, без публікації.

Таблиця: `docs.google.com/spreadsheets/d/180V6ZvXt9H3slJXJVJhV05Eexs_D0dRhPf5DaSGjga0`

Щоб сайт її бачив, у налаштуваннях доступу таблиці має стояти «Усі, хто має
посилання — Переглядач».

Сайт розпізнає колонки за назвами в першому рядку: ім'я або прізвище,
рейтинг, UC, кількість ППО, вартість ППО, всього.

**Чого зараз бракує.** У таблиці немає колонки **«Заклад»**. Через це
рейтинг закладів порожній — сайт чесно пише, що дані ще не додані. Щойно
організатор додасть таку колонку й заповнить її, друга вкладка запрацює
сама. Нічого програмувати не доведеться.

Ще одне налаштування — назва сезону («Осінь 2026»). Вона у файлі
`src/config/ratings.js`, змінюється так само через олівець на GitHub.

## 9. Якщо публікація впала

На сторінці **Actions** біля вашої зміни з'явився червоний хрестик. Це
означає, що сайт **не оновився**, але старий продовжує працювати. Нічого не
зламалося назавжди.

Що робити:

1. Відкрийте https://github.com/Suhrobss/unionize/actions
2. Клацніть верхній запис зі списку
3. Клацніть блок з написом **build**
4. Знайдіть рядок, підсвічений червоним

**Найчастіша причина — помилка в розділових знаках у файлі `.json`.** У
такому разі повідомлення міститиме слово `JSON` і назву файлу.

Як виправити найшвидше: відкрийте свою останню зміну на сторінці **Commits**,
знайдіть, що саме ви редагували, і виправте розділовий знак. Або просто
**скасуйте зміну**: на сторінці коміту праворуч угорі є кнопка **Revert** —
вона поверне все як було.

Якщо не розумієте повідомлення — надішліть мені посилання на невдалий
запуск, я скажу причину.

## 10. Робота на своєму комп'ютері (не обов'язково)

Це потрібно тільки тоді, коли хочете **побачити зміни до того**, як вони
потраплять на сайт.

Один раз відкрийте теку проєкту й запустіть:

```
npm install
```

Далі щоразу, коли хочете подивитися сайт:

```
npm run dev
```

Відкрийте в браузері адресу, яку покаже команда (зазвичай
`http://localhost:4321/unionize`). Сайт оновлюється сам, щойно ви зберігаєте
файл. Щоб зупинити — натисніть `Ctrl+C` у тому ж вікні.

Щоб відправити зміни на сайт:

```
git add -A
git commit -m "коротко, що змінили"
git push
```

Після `git push` публікація почнеться автоматично.

## 11. Коли купите домен

Скажімо, ви купили `unionize.com`. Потрібні три дії:

**1. У панелі, де купили домен**, додайте записи DNS:

| Тип | Ім'я | Значення |
|---|---|---|
| A | @ | 185.199.108.153 |
| A | @ | 185.199.109.153 |
| A | @ | 185.199.110.153 |
| A | @ | 185.199.111.153 |
| CNAME | www | suhrobss.github.io |

**2. На GitHub:** Settings → Pages → Custom domain → впишіть `unionize.com` →
Save. Поставте галочку **Enforce HTTPS** (з'явиться за кілька хвилин, коли
GitHub випише безкоштовний сертифікат).

**3. Скажіть мені** — я поміняю два рядки у файлі `src/config/site.js`, щоб
сайт переїхав із підпапки в корінь домену. Це єдина зміна в коді, яка
знадобиться: всі посилання й зображення побудовані так, що підуть за нею самі.

## 12. Чого краще не робити

**Не видаляйте теки `docs`, `reference` і `scripts` зі свого комп'ютера.**
Їх немає на GitHub — це єдині копії правил, технічних завдань і оригіналу
зображення поля.

**Не міняйте назву репозиторію** без попередження. Адреса сайту прив'язана
до неї; зміна назви зламає всі посилання, доки я не поправлю налаштування.

**Не видаляйте теку `.github`.** Без неї сайт перестане публікуватися
автоматично.

**Не додавайте паролі й ключі у файли проєкту.** Сховище публічне — все, що
туди потрапляє, бачать усі. Для таких речей є окремий механізм, скажіть
мені, якщо знадобиться.

**Не змінюйте кількість питань у тесті архетипу** — підрахунок результату
розбалансується.

**Слово «UnionoPoly» не має зустрічатися ніде.** Гра називається Unionize.

## 13. Що лишилося незакритим

Це не помилки, а речі, які залежать не від коду, а від рішень замовника:

1. **Колонка «Заклад» у таблиці рейтингів.** Поки її немає, рейтинг закладів
   порожній. Додати має організатор турнірів
2. **Домен.** Зараз тимчасова адреса на GitHub
3. **Лічильник рідкості архетипів.** Зараз показуються приблизні відсотки з
   файлу. Щоб рахувати реальні, потрібен безкоштовний проєкт Supabase — скажіть,
   якщо це потрібно, я підключу
4. **Перевірка поширення в сторіз на справжньому телефоні.** У тесті архетипу
   є кнопка «Поділитись у сторіз». Код перевірено, але на реальному пристрої
   ще ні — перевірте й скажіть, чи все гаразд
5. **Три клітинки ППО** мають позначку «чернетка»: на зображенні поля видно
   цифри, але назву закладу прочитати впевнено не вдалося. Треба звірити з
   оригіналом гри
6. **Тексти опису архетипів** написані мною за логікою тесту. Варто, щоб їх
   вичитав хтось із ПРМТУ

## 14. Словник

**Репозиторій (сховище)** — тека з проєктом, що зберігається на GitHub разом
з історією всіх змін.

**Коміт** — одна збережена зміна з підписом, що саме змінилося. Схоже на
точку збереження в грі: до будь-якої можна повернутися.

**Push** — відправка ваших змін на GitHub.

**Actions** — механізм GitHub, що сам збирає й публікує сайт після кожної
зміни.

**Збірка** — перетворення вихідних файлів на готові сторінки. Робиться
автоматично, вам робити нічого не треба.

**JSON** — формат текстових файлів, у якому зберігається зміст сайту.
Вимогливий до ком і лапок.

**DNS** — налаштування, які пов'язують куплений домен із сервером, де лежить
сайт.

**Статичний сайт** — сайт із готових сторінок, без бази даних. Швидкий,
надійний, безкоштовний у розміщенні.
